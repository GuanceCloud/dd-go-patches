# v0.2.3 — verify actual instrumentation use and linked patch sources

This release changes verification, not the Kafka async producer algorithm.
Existing Shopify and IBM patch source files, hashes and supported client/core
profiles are unchanged.

## Fixed false rejections

1. **Unused manual v1 module metadata.** The old verifier rejected any module
   graph containing a v1 tracer other than v1.74.8. A common library can require
   an older v1 module without importing any of its packages. `go mod tidy` then
   removes an explicitly added but unused v1.74.8 requirement and reveals the
   older graph entry. The verifier now checks actual application dependency
   packages. `--inspect` reports `manual_tracer_used` and selected/effective v1
   versions. Actual v1 instrumentation still requires the tested unmodified
   official v1.74.8 shim; unsupported active v1 is not accepted.
2. **Automatic modules omitted from binary build information.** Orchestrion can
   inject packages that cmd/go did not include in the module metadata. When
   metadata alone is insufficient, Linux ELF verification checks Go PC/line
   information: both `WrapAsyncProducer` and its forwarding goroutine must come
   from the selected, hash-validated local source. An absent wrapper or upstream
   unpatched source is rejected. Stripped ELF binaries are supported; unverifiable
   trimmed source paths are rejected rather than treated as success.
3. **Hidden Go diagnostics.** Read-only module/package inspection now includes
   the underlying Go stderr, instead of reporting only a generic failure. URL
   user information, query strings and fragments are redacted.

## Adoption

Upgrade both the versioned archive and its pinned SHA256 in the existing
Dockerfile. Extract/copy the same patch directories and verifier as v0.2.2.
Do not overwrite the old Release assets. Keep existing official package paths.

Run module preparation before read-only verification, then `--inspect`,
`--apply` and the verifier. Use the same application entrypoint, build tags and
module mode for checks and compilation. `pin` and `tidy` can change dependencies:
review their graph diff; do not interpret patch-application drift checks as
covering changes made earlier in the build.

Do not force unused legacy tracer metadata to a newer runtime version merely to
silence the old checker. For actual manual v1 use, the tested shim requirement
still applies. A retained `manual_tracer_used=true` failure needs investigation
of the selected module, replacements and workspace; it is not bypassed.

An extra trailing backslash after a Dockerfile RUN command can absorb the next
RUN instruction. Correct that syntax independently of the verifier upgrade.

## Validation boundary

The verifier's unit/race tests include unused old v1 acceptance, actual old v1
rejection, missing/incorrect binary source provenance and diagnostic redaction.
The unused-v1 fixture exercises tidy, real official automatic weaving and binary
source verification without a Kafka broker. IBM automatic-only fixtures accept
patched normal/stripped binaries and reject unwoven/unpatched binaries.

The producer algorithm is unchanged, so earlier documented Kafka A/B results
remain separate evidence. Private customer applications and their runtime fault
recovery have not been certified by these public fixtures.
