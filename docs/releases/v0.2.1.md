# v0.2.1 — Official-namespace IBM/Sarama patch

Adds an independent IBM AsyncProducer backpressure fix while retaining the
existing Shopify profiles. Upstream module/import paths and APIs are preserved;
this is a local backport, not a DataDog-published tracer release.

## Exact profiles

| Component | Version |
| --- | --- |
| Official Orchestrion | v1.12.1 |
| Official core | v2.10.1 |
| IBM integration / effective IBM client | v2.3.0 + patch / v1.43.2 or v1.44.0 (exact versions) |
| Shopify integration / effective Shopify client | v2.10.1 + patch / v1.23.0 or v1.38.1 |
| Official manual tracer, if present | v1.74.8 |
| Official HTTP integration, when actually used | v2.10.1 |

An actual HTTP integration v2.3.0 dependency has an incompatible ProtectRoundTrip
API with core v2.10.1. Align the HTTP instrumentation module explicitly before
pin/apply; the adapter does not silently change it. Other versions are not
automatically upgraded/downgraded to fit a profile.

## Changes

- Keep at most one pending IBM producer input and send it in a select case so
  successes/errors can still drain during input backpressure. Finish a pending
  unsent span when the wrapper shuts down.
- Discover actual dependencies of the build entrypoint `.` instead of every
  unrelated package. Set PATCH_APP_TARGET for a different build target.
- Select Shopify, IBM, or both only when actually used; unused modules or
  historical replacements do not select a patch.
- Apply selected replacements/imports atomically, preserving existing selected
  and effective business dependencies or rolling back on drift.
- Verify every selected integration/raw client in the real binary and reject
  fork tracer mixing, changed patch sources, and mismatched targets/versions.
- Include both patch source directories, audit diffs, manifests and original
  licenses in the reproducible release archive.

## Validation and boundaries

Local IBM controls used the same 10-worker topology and two-second broker pause:
the original wrapper stalled with all workers occupied; patched and unwrapped
runs each completed 5,000 handlers and 10,000 producer successes, with zero
producer errors and no final stall. These are explicit-wrapper fault tests;
official automatic wrapping and parent links were tested separately.

IBM backpressure/race/vet, upstream real Kafka integration tests, official woven
manual HTTP/gRPC tests, and CGO=0 builds/runs passed. The compatibility fixtures
include gRPC v1.82.1 and an effective v1.57.2 replacement, with HTTP instrumentation
explicitly aligned to v2.10.1. Existing Shopify race/vet and weaving regressions
also passed. No contextStack conversion panic was observed in these fixtures.

This does not certify private applications, every integration, arbitrary versions
or the whole Shopify version interval. Applications must drain producer results.
Retries may produce duplicate downstream records; exactly-once is not guaranteed.
No new DataKit/Dataway/cloud-ingestion or cloud-query verification is claimed.

## Migration from v0.2.0

Download the new archive and verify its pinned SHA256. In addition to the existing
Shopify directory and verifier, copy `third_party/ddtrace-ibm-sarama` into the
application. Merely changing a version/checksum while copying only the old
Shopify directory is insufficient.

For applications using the old HTTP integration, add this explicit instrumentation
baseline alignment before pin:

```dockerfile
RUN go mod edit -require=github.com/DataDog/dd-trace-go/contrib/net/http/v2@v2.10.1
```

Keep business imports, raw Sarama requirements/replacements, private common
libraries, runtime image, application name, environment and command unchanged.
Review pin/bootstrap graph changes separately; --apply preserves the graph it
sees after pin, not every pre-pin version.

The v0.2.0 and older release assets/tags are not replaced.

First-pin validation also observed Orchestrion selecting IBM/Sarama v1.44.0
from an initial v1.43.2 requirement. Both exact versions have independent tests;
the adapter does not force a downgrade or add a business-client replacement.
Review this pin-induced upgrade rather than treating --apply as a guarantee
that every pre-pin business version is unchanged.
